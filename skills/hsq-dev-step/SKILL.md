# 显式逐步执行

## 进入与退出

只有用户当前请求明确要求“一步步做”或不区分大小写的“step by step”才启用。先判断真实意图：否定、引述、解释这些词不触发；“不用一步步”“直接做完”是退出，优先于字面词匹配。任务大、多功能、“拆分任务”“分阶段”都不触发。

启用后持续至全部步骤完成或用户明确退出。后续“继续”只推进下一步，不要求重复关键词。用户已明确授权第一步则开始，不重复问；否则先展示拆分结果，等待确认。退出后恢复普通自主执行，其他 SQL/Spec/高风险/Git 规则仍然有效。

## 步骤计划

盘点功能、依赖、未知项、共享风险和验收，按依赖拆为可独立交付验证的行为步骤，不按文件拆分。每步写目标、范围、预期行为、验证、前置依赖；优先消除关键未知和建立基线。

编号清单状态为 pending / in_progress / blocked / completed，同时最多一个 in_progress。blocked 表示等待用户决策；若 Todo 工具只支持其他状态，用文本清单或计划记录 blocked，工具中保持未完成，不伪造已完成或传入无效枚举。此行为不等于切换 Harness 的计划模式。

## 一次只做一步

1. 只实施已确认的当前步骤，只读当前所需工作流，不提前夹带后续实施或让子 Agent 并行实现后续步骤。
2. 完成最相关的验证后报告本步行为变化、检查结果、风险和对后续的影响，更新状态，并询问是否继续下一步。
3. 新发现改变剩余计划，说明证据、重列未完成步骤并等待确认。
4. 当前步骤发现 Spec 关键前提实质冲突时标 blocked，暂停全部后续实施；只读调查帮助决策，确认方向后更新计划恢复。
5. 每步不自动 commit/push。

最后一步后检查跨步骤组合行为、兼容与文档一致性；已有有效等价证据可以复用，补足缺口，再加载 hsq-dev-deliver 给完整交付总结。
