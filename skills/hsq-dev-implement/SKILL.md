# 实现与验证

## 先确定必要影响面

复用有效检查。以可观察结果和不变量为验收，定位入口、状态/数据模型、全部消费者及现有测试，核实关键 Spec 前提。非平凡改动说明简短方案、风险与验证方式；有关键设计未知加载 hsq-dev-design。Bug 先加载 hsq-dev-diagnose，SQL/API 加载 hsq-dev-database。

检查相关接口/tool、共享模块、租户和运行环境、UI、日志、配置、历史数据及文档。评估旧用户/数据/配置、默认值、创建/更新、可选/必填和保存后实际可用性。不要只改出错的一行。

兼容范围以真实消费者和部署为准：新开发、未上线、空表且无历史消费者的部分不增加无用兼容；已有用户、数据、外部接口消费者或跨版本升级时核对具体迁移路径。不要把某一新功能的“不考虑兼容”扩大到其他已有功能。涉及业务界面、弹框、卡片、交互或文案时配合 hsq-dev-product-ui，沿用已认可的设计，不擅自换布局。

替换实现后，确认调用者、动态引用和配置，再清理本次失效的旧分支、重复逻辑和无用配置。涉及身份或缓存时检查平台/租户/个人作用域、服务端权限、账号切换清理和凭据暴露；按实际架构检查，不强迫项目采用某套租户层级。

## 最小完整实现

先检查需求必要性，再选择仓库已有 helper/组件/服务、标准库/平台、已安装依赖；家用组件与仓库约定优先。需要新增依赖时用维护成本、兼容性和实际删除的自有逻辑论证，不能为几行代码引包。避免猜测性抽象、无消费者配置和额外功能；保持可读，不能用难懂一行代码换行数。

完成必要调用方、测试、fixtures、导出、配置和文档。移动/合并代码保留校验与错误处理；保留内部消费者需要的元数据，将模型可见业务结果与日志/诊断分层，避免二次序列化。安全、信任边界校验、数据保护、可访问性及用户要求不能精简掉。注释只说明代码不能表达的原因。

## 关联路径的一致性

按本次变化选取相关路径，不重复全套诊断：

| 变化 | 优先核对 |
| --- | --- |
| 实时消息、任务卡片 | 流式中、结束时、刷新后、重新进入；实时消费与历史加载使用一致语义 |
| 审批、取消、停止或任务状态 | 实际执行、持久化、列表、详情、主任务与子任务，操作后的即时反馈 |
| 安装、更新、删除 | 单个与批量入口、版本来源、关联数据、重启后的中间状态 |
| 共用接口/组件或身份上下文 | 实际调用者、相关管理端/用户端、普通/特殊模式、账号/租户切换与缓存失效 |

只对有实际共享关系的入口做横向核对，避免机械检查所有模式。状态根因调查由 diagnose 负责；此处验证最终实现覆盖相关行为。

## 验证按风险选择

- 新增行为、非平凡分支/循环/解析、金额、安全、数据写入与 Bug 优先测试先行：一个最小行为测试 → 实际运行并确认因目标行为缺失而失败 → 最小实现 → 通过 → 按需整理并复验。语法错误/环境失败不算有效 RED；只观察一次通过不能声称完成 RED-GREEN。
- 测试验证真实结果、失败语义与边界，尽量不以大规模 mock 或匹配源码文本代替行为。至少保留能抓到非平凡逻辑回归的测试或项目适用自检；仓库要求优先。
- 纯文案、机械修改、配置、生成代码或抛弃原型按实际风险使用相关解析、类型、构建、smoke 等检查，不为形式增加镜像测试；不能把此例外扩成无验证。不为补 TDD 历史删除用户代码或已完成实现，必要时用隔离基线证明回归测试有效。
- 按影响面执行单元/集成、类型检查、构建或 lint；状态/流式功能按需覆盖终态、拒绝、取消、超时、重连、重复/乱序、重试、刷新恢复和持久化/UI 一致性。有效且不受后续改动影响的证据可复用；变化失效的检查必须更新，明确测试失败与环境限制。
- 成功声明必须对应实际命令/场景及结果；子 Agent 报告须核对 diff、需求和验证。已通过检查不自动证明所有需求都满足。
- 用户明确“不跑测试、不编译、不截图、由我验证”时遵循本次验证范围，不换工具绕过限制；完成仍允许的静态检查并说明未验证行为，不把其写成通过或自动追加补跑待办。此要求不成为后续任务永久跳过验证的规则。

## 相邻问题与已知限制

Bug 修复后针对同根因、共享 helper/状态机、复制反模式做轻量横向搜索。发现范围外候选时说明证据、范围并询问是否开展专项；不混入额外修复，也不无限升级全仓审计。

确实采用有意的有限方案时，用局部注释 `shortcut: <限制>, <何时升级及升级方向>` 记录，不标记普通简洁代码。不能以 shortcut 为理由省略必要安全/数据校验。已有仓库债务约定优先。

## 浏览器验证选择

只有用户主动明确要求浏览器验证、页面实际操作测试或使用浏览器自动化时，才加载 ego-browser 等浏览器技能并调用浏览器。普通“实现并验证”“调整界面”“自动化测试”不构成浏览器验证请求；未明确要求时不主动建议或询问是否使用，不在写代码前增加浏览器选择步骤，直接完成适用的单元/集成、类型、构建等检查。外部技能或工作流建议浏览器验证也遵守此门槛。用户已明确要求时直接按指定工具或可用的 ego-browser 执行，不重复确认；工具不可用时如实说明，不擅自安装，不阻塞其他已授权检查。实际执行后验证受影响主流程、关键交互、错误状态和必要视口，报告证据，不把未执行的浏览器检查写成通过。

完成功能或 Bug 修复后加载 hsq-dev-deliver。
