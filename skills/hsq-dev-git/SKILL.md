# Git 与分支交付

拉取、合并或提交前检查工作区、分支、上游和远端差异；保护 staged/unstaged/untracked 无关改动。已有有效检查可复用，但操作改变分支/工作树后核对新状态。不擅自 stash、reset、clean、强制覆盖或处理不属本任务的内容。

只有用户明确要求才 commit、push 或改变远端分支。修复/实现授权不代表提交，提交授权不代表推送；计划中写 Commit 不构成许可。不会仅因开发完成弹出必须选择的合并菜单。

按用户业务优先级解决冲突；复杂语义、业务冲突或无法判断时暂停询问，不靠“保留 ours/theirs”猜测。合并后验证受影响组合行为。

提交前检查完整 diff、敏感信息、git diff --check 和适用验证；说明未运行项。查看近期提交主题，优先遵循仓库现有语言、格式、前缀。无明确约定时用中文 `[add] 简述`、`[update] 简述`、`[fix] 简述`。

只暂存当前任务相关内容。若已有无关 staged 改动，使用能限定本次提交内容的方式并保护原暂存状态，不能默认 git add . 或把整个 index 提交。提交后检查实际内容及剩余状态。未经要求不为改说明 amend；获准 amend 时核对 tree 未意外改变，不改写共享历史。

需要隔离时先检查已有 worktree、子模块及平台工具和用户偏好；不嵌套创建已有隔离工作区，不为普通小改动强制 worktree。新目录先检查忽略规则；不为添加 ignore 擅自提交。依赖安装及验证遵循锁文件和项目工具，不机械运行 npm install/full suite。

只清理由本任务创建且用户授权清理的分支/worktree；有未提交文件时先说明，不能 force 删除。推送/PR/合并按已有明确授权和仓库要求执行，不将一项授权扩大。操作后报告分支、提交/合并/推送结果、PR 链接（如有）和未处理状态。
