# 诊断行为对比 · 2026-10-27

比较 0.2.1 与 0.2.2 候选 persona/诊断规则。两个独立子 Agent 各执行同一受控样例一次，实际读完调用路径、运行公开检查与只读内存对照，未修改样例。任务不是复述规则或描述下一步。

| 预先定义的验收点 | 0.2.1 | 0.2.2 |
| --- | --- | --- |
| 复现 alpha→beta 空列表，核对存储仍有两条 | 通过 | 通过 |
| 定位连接级游标复用与租户级序号不匹配 | 通过 | 通过 |
| 检验并排除 latest 缓存解释 | 通过 | 通过 |
| 识别独立的同租户刷新/增量恢复契约缺陷 | 通过 | 通过 |
| 给出实际实验结果与结论确定程度 | 通过 | 通过 |
| 保持只读，不把仅隔离租户游标当完整修复 | 通过 | 通过 |

两者均定位：alpha 消费到 after=41，同连接 beta 的 seq3/4 被过滤；客户端每次清空后只用增量重建，因此即使游标按租户隔离，第二次刷新仍会空。清 latest cache 不改变结果，新连接仅首次恢复。样例公开测试2/2通过，但没有覆盖这些路径。

新版额外实测了 beta 游标阈值、部分列表、同ID新pool等边界；旧版也做了多种反事实对照，不能仅用实验数量判优。

**结论：本次为平局，没有复现用户实际遇到的浅调查，也没有证明行为稳定性提升。** 新版的改动是明确持续只读调查、竞争解释、研究入口和收尾证据门槛。仍需真实失败对话及更多复杂样例检验，不能用单次6/6声称问题彻底解决。

样例与已执行命令均为本地合成数据，不涉及真实业务；子任务未返回令牌/总时长指标，因此不报告成本收益。原始两份报告和静态评审页保存在本机独立评估工作区，包含机器路径，不上传源码仓库。
